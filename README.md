# 📰 بوت الأخبار الرائجة → فيسبوك

بوت عربي بأربعة مسارات لتوليد المحتوى — **الأخبار** (يستكشف الرائج عالميًا من ٩٤
خلاصة RSS، ويبدأ بمرشّحين مؤقتين تختار أنت منهم قبل إنفاق أي تكلفة صياغة)،
**العاجل** (رادار يفحص تسارع تغطية المصادر كل ~١٥ دقيقة)، **التحقيق** (تلصق موجزًا
تحريريًا بنص Issue فيبحث عنه مصادر مستقلة وينتج حتى منشورين: مقال مصدَّق وتحقيق
مصاحب لما لم يصح منه)، و**التحليل** (يستخلص نقاط نقاش من قنوات تحليل سياسي على
يوتيوب عبر خمس مراحل ويكتب مقالات عربية طويلة منها). كلها تصوغ بالعربية عبر Claude
API، تبني صورة منشور مبرندة، وتعرض عليك المسودة للمراجعة عبر GitHub Issue قبل
النشر على صفحة فيسبوك — بوسم `approved` واحد يشغّل النشر للمسارات الأربعة معًا،
موجَّهًا داخليًا بحقل `origin` في كل مسودة لا بوسم منفصل لكل مسار. إلى جانبها
يبقى مسار أقدم للاستخدام عند الطلب (طلب خبر بكلمات) يشارك نفس نقطة النهاية.
مسار أقدم آخر (تحقق من مقال ملصق) **تقاعد نهائيًا** — راجع قسم «مسارات
متقاعدة» أدناه.

يعمل بالكامل على **GitHub Actions** المجاني، بلا سيرفر وبلا تكلفة استضافة (باستثناء
استدعاءات Claude API، ومفتاح YouTube Data API إن فعّلت مسار التحليل الاختياري).

## كيف يعمل؟

أربعة مسارات محتوى، تمر عبر ما يصل إلى ثلاث بوابات مراجعة، وتتقاطع كلها عند نقطة
نشر واحدة بوسم `approved`:

```
   ┌─ 1) الأخبار (تلقائي عدة مرات يوميًا عبر cron-job.org خارجي) ───────┐
   │  ٩٤ خلاصة RSS → دمج المكرر (جاكارد + دمج دلالي عبر لغات) →         │
   │  ترتيب بمؤشر الترند (منها عوامل الجذب الثلاثة: أثر · قرب · تشويق)  │
   │  → فلترة الذاكرة (٥ أيام) → فرز رخيص (Haiku)                       │
   │       ↓                                                             │
   │  preselect.enabled=true (الافتراضي): يتوقف هنا بمرشّحين مؤقتين —    │
   │  بوابة 🗳️ اختيار بعناوين فقط، تختار أنت ماذا يُصاغ قبل إنفاق أي     │
   │  تكلفة صياغة/صورة (ثلاثة مصائر: 🚀 أول فتحة متاحة · 📝 مراجعة أولية ·│
   │  🎴 بطاقة مباشرة)                                                   │
   └───────────────────────────────────────────────────────────────────┘

   ┌─ 2) العاجل — رادار (كل ~١٥ دقيقة، بلا نموذج إلا عند تجاوز عتبات) ─┐
   │  تسارع تغطية المصادر (بلا LLM) → عتبات صارمة → فرز رخيص →         │
   │  قد يُنشر تلقائيًا بلا مراجعة إن تحققت عتبات أشد (سقف يومي، مصادر   │
   │  مستقلة كافية، ليس مصدرًا رسميًا وحيدًا، تأكد أنه ليس تحديثًا لخبر   │
   │  سابق) — وإلا يدخل بوابة 🗳️ الاختيار نفسها أعلاه                   │
   └───────────────────────────────────────────────────────────────────┘

   ┌─ 3) التحقيق (Issue بوسم مقال — موجز تحريري بالنص لا مقال جاهز) ────┐
   │  استخراج وقائع/رأي الموجز → تسمية أي حدث مُلمَّح إليه من نتائج       │
   │  البحث وحدها → درجة إسناد لكل واقعة (مصدران فأكثر = خبر مباشر ·     │
   │  مصدر واحد = منسوب باسمه في المتن · بلا مصدر = تُستبعد، إلا إن       │
   │  خلت الدرجتان الأخريان تمامًا فتُقبل موسومة «بحسب معلومات المحرر») →│
   │  صياغة مقال مصدَّق من الدرجات المقبولة، ثم — بلا امتناع — محاولة     │
   │  منشور «تحقيق» مصاحب عمّا لم يصح من الموجز                          │
   └───────────────────────────────────────────────────────────────────┘

   ┌─ 4) التحليل — يوتيوب (تشغيل يدوي، خمس مراحل، تجريبي) ──────────────┐
   │  جمع فيديوهات قنوات تحليل سياسي → استخلاص نقاط عربية من النصوص     │
   │  المفرَّغة → عنقدة النقاط بأحداثها الفعلية عبر مصادر/كتل متعددة →    │
   │  كتابة مقال نثري لكل عنقدة بارزة → بطاقة العنوان تُبنى عند الاعتماد │
   │  فقط → drafts/ + Issue مراجعة خاص بوسم youtube-review              │
   └───────────────────────────────────────────────────────────────────┘
                          ↓  (كل المسارات الأربعة تصل هنا)
   ┌─ المراجعة الأولية 📰 (بلا بطاقة بعد) ───────────────────────────────┐
   │  نص قابل للتحرير، ثلاثة عناوين بديلة، مصدر الصورة، رابط صورة يدوي   │
   │       ↓ (اختياري: مربع 🎴 «اعرض البطاقة قبل النشر»)                │
   ┌─ المراجعة النهائية 🎴 (البطاقة مبنية فعليًا) ───────────────────────┐
   │  معاينة أخيرة قبل النشر، ↩️ لإعادته للمراجعة الأولية                │
   └───────────────────────────────────────────────────────────────────┘
                          ↓
   ┌─ النشر (بعد وسم approved على أي Issue مراجعة) ──────────────────────┐
   │  تعليم ✔️ على ما يعجبك (ما لا يُعلَّم يُرفض تلقائيًا — لا خيار        │
   │  استبعاد صريح) → البطاقة تُبنى الآن إن لم تكن بُنيت بعد (cards.ensure)│
   │  → نشر فوري أو مُتباعد الأوقات (طابور queue.yml كل ~١٥ دقيقة، لا     │
   │  فواصل منتظمة كي لا يبدو آليًا) عبر Graph API → تعليق برابط المصدر  │
   │  → إغلاق الـ Issue                                                  │
   └───────────────────────────────────────────────────────────────────┘
```

مسار أقدم لا يزال يعمل عند الطلب، خارج شكل البوابات الثلاث أعلاه (يفتح Issue
مراجعة عادي مباشرة): **طلب بكلمات** (Issue بوسم طلب، بحث Google News
عربي+إنجليزي عن أفضل تطابق) — تفصيله أدناه. مسار مشابه له كان يعمل بالطريقة
نفسها، **تحقق من مقال ملصق**، لكنه تقاعد نهائيًا — راجع قسم «مسارات متقاعدة».

مسارات دعم مستقلة لا تولّد محتوى بنفسها: **استبدال صورة** مسودة موجودة بلا إعادة
صياغة، **تسجيل أسباب الرفض** وتغذيتها لفرز لاحق، **تقرير أداء أسبوعي** من Facebook
Insights يقترح تعديل أوزان `config.yaml`.

## الإعداد — 6 خطوات

### 1) أنشئ المستودع

```bash
git init
git add .
git commit -m "بوت الأخبار الرائجة"
git branch -M main
git remote add origin https://github.com/USERNAME/trendnews.git
git push -u origin main
```

> **المستودع العام أفضل**: معاينات الصور داخل الـ Issue تعمل مباشرة. في المستودع
> الخاص لن تظهر الصور مضمّنة، لكن البوت يرفعها كـ Artifact قابل للتنزيل ويضيف
> رابطها في نص الـ Issue.

### 2) مفتاح Claude API

من [console.anthropic.com](https://console.anthropic.com) → API Keys → Create Key.

### 3) صفحة فيسبوك وتوكن النشر

النشر التلقائي يعمل على **صفحة (Page)** فقط — لا على حساب شخصي.

1. أنشئ تطبيقًا على [developers.facebook.com](https://developers.facebook.com) بنوع
   **Business**، وأضف منتج **Facebook Login**.
2. افتح [Graph API Explorer](https://developers.facebook.com/tools/explorer/):
   اختر تطبيقك، ثم **User Token**، وأضف الصلاحيتين:
   `pages_manage_posts` و `pages_read_engagement`.
3. نفّذ `GET /me/accounts` → انسخ `id` صفحتك (هذا `FB_PAGE_ID`) و `access_token`.
4. **بدّل التوكن إلى طويل الأمد** — التوكن الأولي يعيش ساعتين فقط:

```bash
curl -G "https://graph.facebook.com/v21.0/oauth/access_token" \
  -d "grant_type=fb_exchange_token" \
  -d "client_id=APP_ID" \
  -d "client_secret=APP_SECRET" \
  -d "fb_exchange_token=SHORT_LIVED_PAGE_TOKEN"
```

الناتج هو `FB_PAGE_ACCESS_TOKEN` — توكن صفحة لا تنتهي صلاحيته عادةً، لكنه يُبطل
إذا غيّرت كلمة مرور فيسبوك أو ألغيت صلاحيات التطبيق.

### 4) أضف الأسرار على GitHub

`Settings → Secrets and variables → Actions → New repository secret`

| الاسم | القيمة |
|---|---|
| `ANTHROPIC_API_KEY` | `sk-ant-...` |
| `FB_PAGE_ID` | معرّف الصفحة الرقمي |
| `FB_PAGE_ACCESS_TOKEN` | التوكن طويل الأمد من الخطوة 3 |

`GITHUB_TOKEN` لا يحتاج إعدادًا — يوفّره GitHub تلقائيًا.

### 5) اسمح للـ Actions بالكتابة

`Settings → Actions → General → Workflow permissions`
→ اختر **Read and write permissions** ✔️
→ وفعّل **Allow GitHub Actions to create and approve pull requests** ✔️

بدون هذه الخطوة سيفشل البوت في رفع المسودات وفتح الـ Issues.

### 6) تحقّق قبل أول نشر حقيقي

`Actions → 2️⃣ نشر المعتمد على فيسبوك → Run workflow` مع تفعيل `verify_only ✔️`

إن ظهر اسم صفحتك وعدد متابعيها في السجل، فالتوكن سليم.

## الاستخدام اليومي

**التشغيل تلقائي** لا يعتمد على جدولة GitHub الداخلية (`schedule:` في
`collect.yml`، `radar.yml`، `queue.yml`) لأنها كانت تُسقط المواعيد بلا ضمان؛
بدلًا من ذلك تستدعي خدمة خارجية (cron-job.org) الـ `workflow_dispatch` مباشرة
عدة مرات يوميًا لكل من هذه الثلاثة (الجمع أقل تكرارًا، الرادار والطابور كل
~١٥ دقيقة). لتغيير المواعيد عدّل جدولة المهام في حساب cron-job.org، وليس ملفات
الـ workflow. الاستثناء الوحيد: `insights.yml` (التقرير الأسبوعي) لا يزال يعمل
بجدولة GitHub الأصلية (كل اثنين ٠٧:٠٠ UTC) لأن تكراره منخفض جدًا ليتأثر بالمشكلة.

**للتشغيل الفوري**: `Actions → 1️⃣ جمع الأخبار → Run workflow`

### دورة المراجعة (تشترك فيها كل المسارات)

إن كان `preselect.enabled: true` (الافتراضي)، يفتح مسارا **الأخبار** و**العاجل**
أولًا **Issue اختيار** 🗳️ بعناوين فقط (بلا صياغة ولا صورة بعد) — علّم 🚀 أو 📝 أو
🎴 على ما تريد صياغته كاملًا أو نشره فورًا أو بطاقته مباشرة، واترك الباقي بلا
تعليم، ثم أضف وسم `approved`؛ عندها فقط تُصاغ وتُبنى الصورة لما اخترت. مسارا
**التحقيق** و**التحليل**، وكذلك «طلب» (ومسار «تحقق» سابقًا، قبل تقاعده —
راجع «مسارات متقاعدة»)، يصوغان مباشرة بلا مرحلة اختيار
منفصلة ويفتحان Issue المراجعة الأولية 📰 مباشرة (لمسار التحليل: Issue خاص بوسم
`youtube-review` منفصل عن Issue الأخبار، حتى لا يختلط اعتماد المقالات التحليلية
بغيرها رغم اشتراكهما في وسم `approved` نفسه).

1. يفتح البوت Issue بعنوان `📰 مسودات ...` فيه كل منشور مع صورته ونصه الكامل.
2. علّم ✔️ على المنشورات التي توافق عليها (مربعات الاختيار).
3. أضف الوسم `approved` إلى الـ Issue.
4. ينشر البوت المحدد فقط (بفواصل زمنية عشوائية، لا منتظمة، كي لا يبدو آليًا)،
   يعلّق بروابط المصدر تحت كل منشور، ويغلق الـ Issue.

**قاعدة الفاصل بين المنشورات (30-60 دقيقة) واحدة على كل المسارات عدا العاجل.**
لا فرق بعد اليوم بين الاعتماد عبر Issue، وزر 🚀 «انشر فورًا» في Issue الاختيار،
أو `publish --ids` مباشرة: أيّها يعني «أول فتحة متاحة» — إن لم يمرّ منشور آخر
حديثًا فالنشر فوري، وإلا يدخل الطابور بموعد جديد بعد آخر منشور فعلي بفاصل
عشوائي 30-60 دقيقة (`facebook.gap_min_minutes`/`gap_max_minutes`)، فيلتقطه سيّر
`queue.yml` كما لو كان مجدولًا من الأصل. العاجل وحده يتجاوز هذه القاعدة
وينشر فورًا دومًا. التأجيل ليس رفضًا ولا فشلًا — لا يظهر كخطأ ولا يُسأل عنه
في التقرير الأسبوعي، فقط ينتظر دوره.

مصدر «آخر منشور فعلي» هو `published_at` في مسودات `drafts/` نفسها (يُعاد
حسابه من القرص عند كل استدعاء) — لا ملف حالة مشترك واحد يُكتب مع كل نشر:
سيور النشر تعمل بالتوازي في مجموعات تزامن مختلفة، وملف من هذا النوع يتعارض
بين نشرين متزامنين عند `git pull --rebase`، وقد يعود لموعد أقدم فيضعف
البوابة بدل أن يحميها.

**لمعاينة البطاقة قبل نشرها فعليًا**: تحت مربع ✔️ لكل منشور مربع ثانٍ
«🎴 اعرض البطاقة قبل النشر»، غير معلَّم افتراضيًا (النشر المباشر بعد
الاعتماد هو الأصل). علّمه مع ✔️ ثم أضف وسم `approved` كالعادة — البطاقة
تُبنى كسائر المعتمَد، لكن هذا المنشور تحديدًا لا يُنشر فورًا، بل يبقى
بانتظار Issue ثانٍ بعنوان `🎴 مراجعة نهائية ...` يعرض بطاقته المبنيّة فعليًا
للمعاينة الأخيرة. علّم ✔️ فيه وأضف `approved` لنشره كما هو تمامًا (بلا
إعادة بناء بطاقة ولا اختيار عنوان ولا تعديل نص)، أو علّم ↩️ «أعده للمراجعة
الأولية» لإرجاعه — تُحذف بطاقته القديمة ويعود في أقرب Issue مراجعة أولية
بمربعات العنوان وتعديل النص كاملة (↩️ يغلب ✔️ إن عُلِّما معًا). ما لم
تعلّمه في الـ Issue النهائي يُرفض تلقائيًا كسابقه.

**ما لا تعلّمه ✔️ يُسجَّل مرفوضًا تلقائيًا** (لا خيارات سبب استبعاد في
الواجهة) بوسم «لم يُعتمد» ولن يُنشر — البوت يسأل عن السبب الحقيقي لاحقًا في
التقرير الأسبوعي. لتسجيل سبب حقيقي فورًا بدل الانتظار، اكتب تعليقًا:
`/reject المعرّف السبب`.

**لتعديل نص منشور قبل النشر**: حرّر الـ Issue (زر ✏️) واكتب مباشرة داخل كتلة
النص («📝 نص المنشور الكامل») تحت كل منشور، ثم احفظ. النصّ الذي يراه البوت
لحظة الاعتماد هو ما يُنشر فعليًا — لا حاجة لفتح أي ملف `.json`. تعديل النص لا
يغيّر البطاقة: البطاقة تحمل العنوان فقط.

تحت شارات كل منشور مباشرة يظهر سطر «🖼️ المصدر:» يوضّح من أين جاءت صورة
بطاقته (صورة الناشر الأصلية، صورة تعبيرية حرة الترخيص، رابط وضعته أنت
يدويًا، أو بلا صورة إطلاقًا) — راجعه قبل الاعتماد.

**عناوين مقترحة**: لكل منشور يحمل عناوين بديلة يظهر سطر «📰 العنوان:» يليه
ثلاثة مربعات (الأول بصيغة سؤال ومعلَّم افتراضيًا). علّم البديل الذي تفضّله
قبل الاعتماد ليستبدل سطر العنوان الأول في النص المنشور فعليًا — لا يمسّ هذا
البطاقة، فهي تحمل عنوانها القصير الخاص دومًا. لو حرّرت النص يدويًا وعلّمت
عنوانًا بديلًا معًا، يُطبَّق التحرير أولًا ثم يستبدل العنوان المختار سطره
الأول. مسودة تعذّر توليد عناوين بديلة لها (نادر) لا تعرض هذه المربعات
إطلاقًا وتُنشر بعنوانها الأصلي وحده.

**لتجاهل الدفعة كلها**: أغلق الـ Issue بلا وسم — الأسباب المكتوبة (إن وُجدت)
تُسجَّل وتُغذّي فرز المرات القادمة.

**لاستبدال صورة مسودة**: تحت كل منشور في الـ Issue مربعٌ وفراغ:

```
- [ ] 🖼️ استبدل الصورة بالرابط أدناه
    الرابط:
```

حرّر الـ Issue (زر ✏️)، الصق رابط صورة مباشر بعد كلمة «الرابط:» واحفظ، ثم
علّم المربع. يُعاد بناء البطاقة على صورتك خلال دقيقة، وتُحدَّث الصورة في
الـ Issue، ويُفرَّغ المربع تلقائيًا. النص لا يُعاد صياغته — الصورة وحدها
تتغير، فلا استدعاء للنموذج ولا تكلفة. البديل لمن يفضّله: تعليق فيه
`/صورة المعرّف الرابط`.

المسودات التي وصلت بلا صورة صالحة يعلوها تنبيه «بلا صورة للخبر»، وبطاقتها
مبنية على خلفية مصممة. الرابط يجب أن يكون لصورة مباشرة (تنتهي بـ `.jpg`
أو `.png`) لا لصفحة تحتوي صورة: في المتصفح زر أيمن على الصورة ← «نسخ عنوان
الصورة».

### إحياء منشور فشل نشره على فيسبوك (♻️)

منشور اعتمدتَه فعلًا وبُنيت بطاقته، لكن نشره الفعلي على فيسبوك فشل (توكن
منتهٍ، عطل مؤقت في الواجهة، …) لا يضيع صامتًا. يفتح البوت — في نفس تشغيلة
فتح Issue المراجعة العادية — Issue مستقل بعنوان `♻️ منشورات فشل نشرها ...`
بوسم `failed-review`، فيه مربع «♻️ أعد المحاولة» لكل منشور فشل نشره، مع
عمره منذ الفشل ونص الخطأ وبطاقته الجاهزة للمعاينة.

- علّم ✔️ على ما تريد إعادة محاولته، ثم أضف وسم `approved` — يعود المنشور
  إلى طابور النشر العادي بموعد بعد آخر ما هو محجوز فيه (لا نشر فوري).
- **ما لا تعلّمه يموت نهائيًا** — لا خيار استبعاد مؤقت هنا، ولا إعادة عرض
  لاحقة. إغلاق الـ Issue بلا وسم `approved` يعني موت الدفعة كلها بالمثل.
- إن كان سبب الفشل توكن فيسبوك نفسه، أصلحه (راجع القسم ٣ أعلاه) **قبل**
  وضع وسم `approved`، وإلا فشلت إعادة المحاولة بالسبب نفسه.
- الإخفاقات القديمة (من قبل هذه الميزة) لا تظهر هنا إطلاقًا — فقط فشل
  النشر الفعلي على فيسبوك تحديدًا يُعرَض؛ منشور فشل لنقص حقل أساسي أو
  لغياب صورته له مساراه الخاص (تعديل يدوي، أو `/صورة`) لا هذا.
- منشور أُعيد فنُشر بنجاح ينتهي أمره هنا. منشور أُعيد ففشل ثانية يُعرَض
  مرة أخيرة فقط — بعدها لا يُعرَض مجددًا ويبقى بحاجة تدخل يدوي.

### رادار العاجل — نشر بلا مراجعة بشرط عتبات صارمة

يعمل تلقائيًا (`radar.yml`) بلا تدخل — يفحص تسارع تغطية المصادر لعيّنة من
المصادر الموثوقة بلا أي استدعاء نموذج، ولا يكلّف شيئًا إلا حين يتجاوز خبر عتبات
السرعة/الدرجة/عدد المصادر (`config.yaml: radar`). حتى عندها، النشر التلقائي
بلا مراجعة بشرية له عتبات أعلى بكثير ومنفصلة (`auto_publish_min_score`,
`auto_publish_min_sources`)، ويُرفض تمامًا لو: تجاوز السقف اليومي، المصدر رسمي/
حكومي وحيد، الخبر من فئة «خفيفة»، تعذّرت قراءة نص المصدر، أو تبيّن أنه تحديث
لخبر منشور سابقًا لا خبر جديد. أي خبر يجتاز الفحص الرخيص لكنه لا يجتاز عتبات
النشر التلقائي يُحفظ كمرشّح لدورة الاختيار العادية بدل إهدار العمل المُنجَز فيه.

**للتشغيل الفوري (فحص بلا نشر)**: `Actions → 🚨 رادار العاجل → Run workflow` مع
`dry_run ✔️`.

### لطلب خبر بنفسك (عكس الدورة العادية — أنت تحدد الموضوع لا الخلاصات)

- `Actions → طلب خبر بكلمات → Run workflow` واكتب الكلمات في الخانة.
- أو افتح Issue عنوانه هو الكلمات وضع عليه الوسم `طلب` — أسهل من الهاتف.

يبحث البوت في خلاصة بحث Google News بالعربية والإنجليزية معًا (بلا
مفتاح وبلا تكلفة)، ويصوغ مسودة من أقوى نتيجة ثم يعرضها للمراجعة كالمعتاد.
خيار `dry_run` يعرض نتائج البحث بلا صياغة — مجاني تمامًا، مفيد لتجربة
صياغة الكلمات قبل إنفاق استدعاء. الإعدادات في `config.yaml` تحت `request`:
نافذة البحث بالأيام، وعدد كلمات الطلب التي يجب أن تظهر في الخبر، ولغات البحث.

### تحقق من مقال ملصق — مسار متقاعد

كان هذا المسار (Issue بوسم `تحقق`) يبحث ويقرر ثم يصوغ مسودة من المؤكَّد
وحده. **تقاعد نهائيًا** — راجع قسم «مسارات متقاعدة» في آخر هذا الملف
للتفصيل الكامل وللبديل الحي (مسار التحقيق أدناه).

### مسار التحقيق — مقال من فكرتك (موجز تحريري، لا مقال جاهز للتحقق منه)

- افتح Issue جديد، اكتب فكرتك ومعلوماتك ورأيك في جسمه (هذا **موجز**، وليس
  نصًا جاهزًا يُحقَّق منه حرفيًا كما في مسار «تحقق»)، وضع عليه الوسم `مقال`.
- يستخرج البوت من الموجز وقائع ورأيك المُعبَّر عنه، وإن أشرت لحدث بلا تسميته
  صراحة (مثل «الاجتماع الأخير») يحاول تسميته من نتائج بحث مستقلة فقط — أبدًا
  من معرفة النموذج المسبقة.
- **درجة إسناد لكل واقعة، لا حذف صامت**: واقعة سُمّيت في موجزك أو اكتُشف اسمها
  ولها مصدران مستقلان فأكثر (`article.min_confirm_sources`) تُدرَج كخبر مباشر
  بلا أي وسم؛ واقعة بمصدر واحد فقط تُدرَج منسوبة باسمه صراحة في المتن؛ واقعة
  بلا أي مصدر تُستبعد من المقال ويذكر التقرير السبب — **إلا** إن انتهت كل
  الوقائع بلا واقعة واحدة بمصدرين فأكثر، فعندها تُقبل وقائع موجزك كلها موسومة
  «بحسب معلومات المحرر» بدل الامتناع الكامل عن المقال.
- من الوقائع المقبولة يختار البوت سؤال العنوان ويصوغ مقالًا جديدًا (`origin:
  "article"`)، يُدمج فيه رأيك منسوبًا صراحةً («ويرى كاتب الموجز أن...») لا
  منسوخًا، ما لم تُعطِّل هذا بـ `article.include_opinion: false`. فحص أصالة
  لفظي (نفس آلية مسار «تحقق») يرفض أي عبارة منسوخة حرفيًا من موجزك أو من مصدر
  واحد بعينه.
- **ثم، بلا شرط ولا امتناع**، يحاول البوت منشورًا ثانيًا مستقلًا — «تحقيق» —
  عمّا لم يصح من موجزك (وقائع تعارضت معها المصادر أو تعذّر تأكيدها)؛ يُكتب
  فقط إن وُجد فعلًا ما يستحق ذكره، وممنوع عليه استخدام كلمات النفي
  (كاذب/مفبرك/شائعة) أو تسمية مصدر واقعة غير مُسندة. المنشوران يدخلان دورة
  المراجعة العادية معًا. الإعدادات في `config.yaml` تحت `article`، والكود في
  `src/article.py`.

## مسار التحليل — يوتيوب (تجريبي، إعداد منفصل واختياري)

على عكس المسارات الثلاثة أعلاه، هذا المسار لا يعمل بمجرد إعداد الخطوات الست
الأساسية — يحتاج مفتاح YouTube Data API إضافيًا، ومستودعًا خاصًا ثانيًا لتخزين
بيانات القنوات (نصوص مفرَّغة واقتباسات حرفية من مواد قنوات طرف ثالث محمية
بحقوق نشر لا يصح أرشفتها علنًا)، ويُشغَّل يدويًا لا تلقائيًا (أسماء ملفات
الـ workflow تحمل «تجريبي» عمدًا). إن لم تحتَجه تجاهل هذا القسم كليًا — بقية
البوت يعمل دونه بلا أي تأثير.

**الإعداد**: أضف السرّين `YOUTUBE_API_KEY` (من Google Cloud Console، فعّل
YouTube Data API v3) و`YOUTUBE_DATA_TOKEN` (Personal Access Token بصلاحية
`repo` على مستودع بيانات خاص منفصل، مثل `<حسابك>/trendnews-data`، تُنشئه
بنفسك لتخزين النصوص المفرَّغة) إلى أسرار المستودع، وسرّي
`WEBSHARE_PROXY_USERNAME`/`WEBSHARE_PROXY_PASSWORD` (بروكسي مدفوع رخيص —
يوتيوب يحظر عناوين IP مستضافات GitHub Actions من جلب النصوص المفرَّغة
مباشرة)، ثم أضف قنوات المتابعة تحت `channels` في `config.yaml` (المعرّف
والاسم واللغة والكتلة `bloc` وأنماط عناوين تُستبعد كالنشرات المباشرة).

**التشغيل** ثلاث مراحل يدوية بالترتيب:

1. `Actions → 🎥 جمع واستخلاص يوتيوب → Run workflow` — يجلب فيديوهات القنوات
   النشطة، يستخلص ٥-٧ نقاط عربية من كل نص مفرَّغ، ويحفظها في مستودع البيانات
   الخاص.
2. `Actions → 📰 عنقدة وكتابة مقالات يوتيوب → Run workflow` — يعنقد النقاط
   بالحدث الفعلي الذي تصفه (لا بمجرد تشابه الموضوع)، يصنّفها بطبقة تنوّع
   (عبر كتل/قنوات متعددة أو قناة واحدة) ونوع اتفاق، يكتب مقالًا نثريًا
   لأبرزها، ويفتح Issue مراجعة بوسم `youtube-review` بعناوين بديلة لكل مقال —
   بلا صورة بعد.
3. علّم ✔️ على ما تختاره في ذلك الـ Issue وأضف وسم `approved` كالمعتاد؛ عندها
   فقط تُبنى بطاقة العنوان (`Actions → 📰 نشر مقالات يوتيوب المعتمدة → Run
   workflow` مع رقم الـ Issue) وينشر المقال.

الإعدادات في `config.yaml` تحت `youtube`/`channels`، والكود في
`src/youtube_collect.py` → `youtube_extract.py` → `youtube_cluster.py` →
`youtube_article.py` → `youtube_publish.py` بهذا الترتيب بالضبط — كل مرحلة
تستهلك ملف مخرجات المرحلة السابقة.

## مسارات متقاعدة

### تحقق من مقال ملصق (`src/verify.py`)

صاحب المشروع قرر **تقاعد هذا المسار نهائيًا**. وسم Issue بـ`تحقق` لم يعد
يشغّل شيئًا — `.github/workflows/verify.yml`، مشغّله الوحيد، حُذف عمدًا. من
يريد نتيجة مشابهة اليوم (بحث مستقل قبل الصياغة) يستعمل **مسار التحقيق**
أعلاه (Issue بوسم `مقال`) بدلًا منه.

الكود نفسه لم يُحذف ولن يُحذف: `src/verify_draft.py` يبقى **حيًّا ومستعمَلًا
فعليًا** من مسار التحقيق — `src/article.py` يستورده مباشرة ويعيد استعمال
فحص الأصالة منه (`check_originality`) ودوال اختيار الصور
(`_normalized_words`/`_image_candidates`). حذف `src/verify.py` كان سيكسر ذلك
الاستيراد بالتبعية: `verify_draft.py` يستورد `STATUS_CONFIRMED`
و`_TASHKEEL_RE` من `verify.py` مباشرة. مفاتيح `verify`/`verify_draft` في
`config.yaml`، وشارة «تحقيق» الخاصة بـ`cards.verify` على البطاقة، بقيت
كذلك بلا حذف — حذفها كان يكسر نفس الاستيرادات وقد يُخفي أثرًا نحتاجه لو
أُحيي المسار يومًا.

تشغيل `src/verify.py` ممكن **يدويًا فقط** من سطر الأوامر
(`python -m src.verify --issue رقم`)، ويطبع تحذيرًا صريحًا بالتقاعد عند كل
تشغيل بلا منع التنفيذ. ولأن `.github/workflows/verify.yml` حُذف، فإن مرحلته
الثانية (صياغة مسودة من المؤكَّد، `verify_draft.attempt`) ترفض الكتابة
افتراضيًا حتى في التشغيل اليدوي — حارسها يتطلب متغيّر بيئة
`VERIFY_DRAFT_WRITE_ENABLED=true` كان يُعلَن من ذلك الـ workflow، ولا شيء
يُعلنه الآن؛ من يريد تشغيلها يدويًا فعليًا عليه تصديره بنفسه أولًا.

كان المسار يعمل بمرحلتين: **تقرير** يبحث عن كل واقعة في المقال الملصق في
مصادر مستقلة ويحكم عليها (مؤكَّدة/مؤكَّدة مع اعتراض مصدر/شبه مؤكَّدة/مصدر
واحد/لا مصدر/يخالفها مصدر)، ثم — إن كفى المؤكَّد منها (واقعتان مستقلتان
بمصدرين فأكثر لكل منهما) — **مسودة** منشور من المؤكَّد وحده بلا أي كلمة من
المقال الملصق نفسه (دالّة الصياغة لا تستقبل نص المقال في توقيعها أصلًا).

⚠️ **خلل تقني معروف لم يُصلَح عمدًا** (توثيق فقط — لا إصلاح منطقي، لأن
المسار متقاعد): دالّتا الحكم `judge_fact`/`judge_question` في `src/verify.py`
تستدعيان النموذج بسقف توكنات ثابت (500 و400 على التوالي) بلا فحص
`stop_reason` — رد نموذج بُتر بسبب هذا السقف يعود بنفس بنية «لا مؤيِّد ولا
مخالف»/«لا إجابة» التي يعيدها حكم شرعي فعلي، فلا يمكن تمييز الفشل التقني عن
الحكم الحقيقي حاليًا (`judge_question` أضعف: قيمتها الافتراضية عند الفشل لا
تحمل حقل `call_error` أصلًا). من أحيا هذا المسار يومًا فليصلح هذا أولًا —
الوصفة في Issues #1050 و#1052 و#1061.

## التخصيص — `config.yaml`

كل شيء يُضبط من ملف واحد بلا لمس الكود — أكثر من ٢٠٠ مفتاح موزّعة على أقسام
`brand` (المصادر ٩٤ خلاصة)، `trends`، `selection` (فيها `selection.appeal`)،
`preselect`، `writer`، `headlines`، `request`، `verify`، `verify_draft`،
`article`، `radar`، `merge`، `screening`، `reading`، `analysis`، `image`،
`cards`، `reel`، `image_search`، `facebook`، `decisions`، `names`، وقسما مسار
التحليل `youtube`/`channels`. أبرزها:

| الإعداد | ماذا يفعل |
|---|---|
| `brand.name` / `handle` | الاسم والمعرّف على الصورة |
| `brand.primary_color` / `accent_color` | لون الشريط ولون التمييز |
| `sources` | أضف/احذف خلاصات RSS، وحدّد `region` و `weight` و `state_media` لكل مصدر |
| `preselect.enabled` | `true` يفتح Issue اختيار 🗳️ بعناوين فقط قبل الصياغة (توفير تكلفة)؛ `false` يعود للمسار القديم (صياغة الدفعة كاملة) |
| `selection.drafts_per_run` | عدد المسودات في كل تشغيل |
| `selection.min_sources_for_trend` | ارفعه لنشر ما تتفق عليه عدة مصادر فقط |
| `selection.max_age_hours` | أقصى عمر مقبول للخبر |
| `selection.dedupe_memory_days` | مدة منع إعادة نشر خبر مشابه |
| `selection.blocklist_keywords` | كلمات تستبعد الخبر تمامًا |
| `selection.appeal.impact_weight` / `proximity_weight` / `intrigue_weight` | أوزان عوامل الجذب الثلاثة (أثر · قرب · تشويق) في مؤشر الترند؛ صفّرها للعودة للسلوك القديم |
| `writer.model` | `claude-sonnet-5` للجودة، أو `claude-haiku-4-5-20251001` للتوفير |
| `writer.tone` | نبرة الكتابة العربية |
| `radar.auto_publish` | `false` يعطّل النشر بلا مراجعة نهائيًا (يبقى الفحص/الصياغة فعّالين) |
| `radar.auto_publish_daily_limit` | سقف عدد المنشورات المنشورة تلقائيًا يوميًا |
| `verify.min_confirm_sources` (مسار متقاعد) / `article.min_confirm_sources` | عدد المصادر المستقلة المطلوب لاعتبار واقعة «مؤكَّدة» (تحقق، متقاعد) أو خبرًا مباشرًا بلا وسم إسناد (مقال) |
| `article.include_opinion` | إدراج رأي كاتب الموجز في المسودة منسوبًا أم لا |
| `article.editor_tag_phrase` | نص وسم الوقائع بلا مصدر عند قبولها استثناءً («بحسب معلومات المحرر») |
| `cards` | شارة/لون كل نوع مسودة على البطاقة، بمفتاح `origin` (`news`/`breaking`/`article`/`analysis`) |
| `image_search.providers` | مصادر الصور الاحتياطية عند غياب صورة من الناشر (ويكيميديا/Openverse فقط) |
| `facebook.schedule_mode` | `burst` (فاصل عشوائي بين المنشورات) أو أنماط أخرى |
| `facebook.gap_min_minutes` / `gap_max_minutes` | الفاصل الأدنى/الأعلى (دقائق) الذي تفرضه بوابة الفاصل الواحدة بين أي منشورَين غير عاجلَين، على كل المسارات |
| `youtube.lookback_hours` / `channels` | نافذة جلب فيديوهات مسار التحليل، وقائمة القنوات المتابَعة |
| `names.aliases` | معجم يدوي لتوحيد رسم أسماء الأعلام (راجع القسم التالي) |
| `names.blocklist` | أسماء مستبعدة من التعلّم الآلي (تُلغي مدخلًا متعلَّمًا فورًا حتى لو كان مخزَّنًا) |
| `names.learned_enabled` | يوقف طبقة التعلّم الآلي كلها إن صار `false`، بلا مسّ المعجم اليدوي |
| `names.seen_keep_days` | مدة الاحتفاظ بعدّ ورود الأسماء (`state/names_seen.json`) — 90 يومًا افتراضيًا |

### توحيد رسم أسماء الأعلام

كل مسار يصوغ نصه بنموذج مستقل، فقد يخرج اسم العلم نفسه برسمين مختلفين بين
مسودتين متتاليتين («نتنياهو» مقابل «نتانياهو» مثلًا) — فرق يظهر للقارئ مباشرة
على البطاقات. التوحيد يقع في طبقتين تُدمجان معًا (`src/names.py`)، **اليدوية
تغلب المتعلَّمة دائمًا عند التعارض**:

**١) الطبقة اليدوية** — `config.yaml: names.aliases` معجم بسيط: "الرسم
المعتمد": [كل الرسوم البديلة الواجب استبدالها به]. لإضافة اسم جديد، أضف سطرًا
هنا بلا لمس أي شيفرة:

```yaml
names:
  aliases:
    "نتنياهو": ["نتانياهو", "نيتنياهو"]
```

**٢) الطبقة المتعلَّمة** (`src/names_learn.py`، لا صيانة يدوية) — تكتشف
رسمين لاسم علم واحد آليًا من تكرارهما الفعلي في المسودات. كل مسودة تُسجِّل
عدّ كلمها العربية الطويلة (≥ 5 أحرف) في `state/names_seen.json` عند الحفظ
(قبل أي توحيد)، وفي نهاية كل دورة جمع أخبار (مرة كل 24 ساعة على الأكثر)
يرشِّح `src.collect` أزواج كلمات تجتاز حواجز عددية (تكرار كافٍ، نسبة تفوّق
واضحة) وحاجز تشابه إملائي (مسافة ليفنشتاين ≤ 2)، ثم يسأل نموذجًا رخيصًا حكمًا
واحدًا لكل زوج: هل هما رسمان لاسم علم واحد، أم تصريف نحوي، أم كلمتان
مختلفتان تمامًا؟ لا يُقبل إلا الجواب الأول. النتيجة تُخزَّن في
`state/names_learned.json` بالرسم الأكثر ورودًا معتمَدًا.

**لإلغاء اسم تعلّمه البوت خطأً** (أو منع تعلّمه إطلاقًا): أضفه إلى
`config.yaml: names.blocklist` — يُلغي أي مدخل متعلَّم فورًا حتى لو كان مخزَّنًا
سلفًا، بلا مسّ المعجم اليدوي. **لإيقاف طبقة التعلّم كلها** بلا مسّ اليدوي:
`names.learned_enabled: false`.

**أين تظهر الأسماء التي تعلّمها البوت:** في التقرير الأسبوعي (`insights.py`)،
سطر واحد لكل اسم وُحِّد رسمه خلال الأسبوع بالشكل «📝 وُحّد الرسم: نتانياهو ←
نتنياهو (70 مقابل 2)» — بلا أي سطر إن لم يتعلّم شيئًا.

يُطبَّق هذا التوحيد (بطبقتيه معًا) مرة واحدة فقط، عند الحفظ
(`store.save_draft`/`update_draft` في `src/names.py`)، فيشمل كل مسار تلقائيًا
— الأخبار والعاجل والتحقيق والطلب ومسار التحليل (يوتيوب) على حد سواء — بلا
حاجة لتعديل أي كاتب نص بمفرده. الاستبدال نصّي مباشر (لا همزات، لا تشكيل، لا
أي تطبيع لغوي آخر)، ولا يمسّ إلا حقول النص العربي المعروضة على القارئ:
`arabic.post_title`/`body`/`caption`، `caption`، و`headlines` — أبدًا رابط
المصدر أو الصورة أو معرّف المسودة أو اسم الناشر.

### إضافة مصدر جديد

```yaml
  - name: "Sky News Arabia"
    url: "https://www.skynewsarabia.com/rss"
    region: "mena"
    weight: 1.0
```

`region` يُستخدم للتنوع الجغرافي (سقفه `max_per_region`)، و `weight` يرفع أو
يخفض أولوية المصدر في مؤشر الترند. `state_media: true` (اختياري) يخفض الدرجة
قليلًا ويظهر تنبيهًا في الـ Issue، دون استبعاد المصدر.

## تفاصيل تقنية تستحق الانتباه

**النص العربي على الصورة** — يحتاج `arabic-reshaper` لوصل الحروف و `python-bidi`
لاتجاه الكتابة (أو تشكيل RTL أصلي عبر Raqm إن توفّر). المهم: تقسيم الأسطر يجري
على النص المنطقي **قبل** التشكيل، وإلا انكسرت الكلمات وظهرت الحروف منفصلة.

**ترتيب خطوات الـ workflow** — الصور تُرفع للمستودع **قبل** فتح الـ Issue، وإلا
ظهرت المعاينات كـ 404 لأن روابط `raw.githubusercontent` لم توجد بعد.

**ترتيب التحقق قبل اختيار السؤال (مسار «مقال»)** — تصفية الوقائع بعدد المصادر
تجري **قبل** اختيار الواقعة المحورية للعنوان، لا العكس؛ وإلا قد يُختار عنوان
حول واقعة لم تُتحقَّق فعليًا لمجرد أنها اختيرت أولًا.

**القص** — يميل للثلث الأعلى من الصورة لأن الوجوه غالبًا هناك، مع تدرّج تعتيم
أسّي (لا خطّي) يضمن قراءة النص فوق أي صورة بأي سطوع.

**البرومبت** — يمنع اختراع الأرقام والتصريحات، يمنع النسخ الحرفي من المصدر، ويعيد
`newsworthy: false` للأخبار التافهة أو الترويجية فيتخطّاها البوت تلقائيًا.

**مؤشر الترند** — `3×log₂(عدد المصادر) + 2×log₂(عدد المناطق) + 1.5×وزن المصدر +
2×الحداثة + وزن الترند×تطابق بحث جوجل + وزن السرعة×تسارع المصادر + 0.8 إن وُجدت
صورة`. اللوغاريتم يمنع سيطرة خبر واحد تغطيه عشرات الوكالات.

**لا `temperature` أبدًا** — النماذج المستخدمة هنا ترفضه بخطأ 400؛ اختبار ثابت
(`test_no_temperature_param`) يفشل الحزمة كلها لو ظهر مجددًا في أي استدعاء نموذج.

**الحذف الدوري (`src/retention.py`)** — كل تشغيلة (`python -m src.retention`) تحذف من `drafts/`
وَ`state/candidates/` ما تجاوز نافذة واحدة، `config.yaml: retention.days` (الافتراضي 30 يومًا)؛
`--dry-run` يطبع ما سيُحذف بلا حذف فعلي. النافذة لا يجوز أن تقلّ عن 30 لأن تقرير الأداء الأسبوعي
(`insights.py`) يقرأ افتراضيًا آخر 30 يومًا من المنشورات — طلب تقرير يدوي بمدة أطول من
`retention.days` لن يجد منشورات أقدم منها. قاعدة العمر: المسودة المنشورة (`status: "published"`)
تُقاس من `published_at`، والمسودة قيد الطابور (`status: "queued"`) لا تُحذف أبدًا مهما بلغ عمرها،
وأي حالة أخرى (`pending`، `failed`، `rejected`…) تُقاس من تاريخ مجلد يومها. تُحذف المسودة وحدة
واحدة — ملف الـ JSON مع كل صورها في نفس مجلد اليوم — فلا يبقى ملف يشير إلى صورة محذوفة.

## حل المشاكل

| المشكلة | السبب والحل |
|---|---|
| فشل رفع المسودات | فعّل **Read and write permissions** (الخطوة 5) |
| الصور لا تظهر في الـ Issue | مستودع خاص — نزّلها من Artifacts في صفحة التشغيل |
| `خطأ فيسبوك [190]` | التوكن انتهى — أعد توليده كتوكن طويل الأمد |
| `خطأ فيسبوك [200]` | صلاحيات ناقصة — أضف `pages_manage_posts` |
| مربعات مربعة بدل الحروف | الخطوط مفقودة — شغّل `bash scripts/fetch_fonts.sh` |
| `لم يُجلب أي خبر` | مصدر RSS تغيّر رابطه — تحقّق من `sources` في `config.yaml`، أو شغّل `python -m src.check_sources` لفحص كل الخلاصات دفعة واحدة |
| مسودات قليلة جدًا | خفّض `min_sources_for_trend` أو ارفع `max_age_hours` |
| Issue اختيار 🗳️ بدل Issue مراجعة أولية عادي | `preselect.enabled: true` — هذا متوقَّع؛ عطّله لو تفضّل الصياغة المباشرة |
| وسم Issue بـ`تحقق` لا يشغّل شيئًا | متوقَّع — مسار «تحقق» تقاعد نهائيًا (راجع «مسارات متقاعدة»)؛ مشغّله `verify.yml` محذوف عمدًا |
| مسار التحليل (يوتيوب) لا يعمل | تحقّق من أسرار `YOUTUBE_API_KEY`/`YOUTUBE_DATA_TOKEN`/`WEBSHARE_PROXY_USERNAME`/`WEBSHARE_PROXY_PASSWORD` — هذا المسار وحده يحتاجها |

## ملاحظتان مهمتان

**سياسة فيسبوك**: النشر الآلي المكثف لأخبار منسوخة قد يُخفّض وصول الصفحة أو
يعرّضها للتقييد. البقاء عند عدد منشورات معقول يوميًا مع صياغة أصلية (وهو ما
يفرضه البرومبت) وفواصل زمنية غير منتظمة (`schedule.py`) أكثر أمانًا من رفع
العدد.

**الدقة الصحفية**: النموذج قد يخطئ في نقل تفصيل أو اسم. مسار المراجعة موجود
لهذا السبب تحديدًا — اقرأ النص قبل الاعتماد، خاصة في الأخبار الحساسة سياسيًا.
مسار «مقال» (التحقيق) يقلّص هذا الخطر ببحث مستقل قبل الصياغة، لكنه لا يلغيه:
راجع التقرير المرفق دائمًا. مسار «تحقق» كان يقدّم الشيء نفسه قبل أن يتقاعد
(راجع «مسارات متقاعدة»).
